## Known limitations and corrections disclosed in the paper

1. Simulation study; radio energy estimated from datasheet currents, not measured.
2. Loss chains fitted on one farm, three months, 174 MHz PHY; Markov continuous-time conversion.
3. Composite workload (CAF, USCRN, UWA, Azure not co-located); synthetic thresholds/zones/deadlines.
4. Task work values are conservative: the simulations used 15.5 s per field map (an early timing taken
   under CPU load) while the idle profile is 1.9 s, and 5 ms per verification vs 30 µs profiled.
   Heavier tasks only make placement harder; stated in Sec. 6 and `config/default.yaml`.
5. Default BRISK heartbeat range chosen from a single-seed pilot for iso-energy; full trade-off curves reported.
6. Negative results reported: no significant alarm-time accuracy gain over suppression; scoped Class-B
   variant worse; urgent delivery bounded by node-side outages for all policies.
7. Scalability beyond 6 fields replays time-shifted copies of the same years.
8. Container restart during the sensitivity study: interrupted jobs were rerun; the runner skips
   completed (policy, variant, seed) rows, so no run is duplicated or mixed.
